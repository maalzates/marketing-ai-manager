Configurar Google Cloud

Nueve pasos en orden. Haz uno, pasa al siguiente. No saltes: la consola bloquea los pasos posteriores hasta que los anteriores están hechos.

Consola console.cloud.google.com Tiempo ~15 min Etiquetas en inglés, como las muestra la consola

Dónde está todo

Menú ☰ → Google Auth Platform. Ahí viven Overview, Branding, Audience, Clients y Data access. Solo el paso 5 está en otro sitio: APIs & Services → Library.

Si un tutorial te manda a «APIs & Services → OAuth consent screen», es de la consola anterior. Ya no existe.

1 Crear o elegir el proyecto

  1. Entra en console.cloud.google.com.
  2. Selector de proyecto, arriba a la izquierda, junto al logo.
  3. Si no hay proyecto: New project → nombre libre → Create.

Un solo proyecto para local y producción. Todo lo demás cuelga de él.

2 Configurar Google Auth Platform

Esto es lo que la consola exige antes de dejarte crear el cliente o publicar. Si ya lo hiciste, salta al paso 3.

  1. Menú ☰ → Google Auth Platform.
  2. Botón Get started.
  3. Rellena las cuatro pantallas con la tabla de abajo.
  4. Botón Create.
Pantalla Campo Qué poner
App Information App name Marketing AI Manager — esto sí lo ve el usuario en la pantalla de consentimiento. No puede contener «Google».
User support email Tu correo, del desplegable.
Audience Audience External. «Internal» solo sirve dentro de una organización de Workspace.
Contact Information Email addresses Tu correo. Aquí llegan los avisos de Google sobre el proyecto.
Finish Casilla de las políticas Marcar y Continue.

3 Revisar Branding

  1. Google Auth Platform → Branding.
  2. Rellena los cinco campos de la tabla. Terms of service se queda vacío.
  3. Save.
Campo Valor
App name MazzeFlow AI Marketing — sin flechas ni símbolos raros, y sin la palabra «Google».
User support email Tu correo, del desplegable.
Application home page https://mazzeflow.com
Application privacy policy link https://mazzeflow.com/privacy
Application terms of service link Vacío. No es obligatorio.
Authorized domain 1 mazzeflow.com — sin https:// y sin barra final.
App logo Vacío. Subirlo obliga a pasar verificación.

Estos cuatro no son opcionales

Google lo dice en el tooltip del botón Publish app:

Valid app name, support email, homepage url, and privacy policy url
are required for switching the app to external production mode.

Si falta alguno, Audience muestra «Your app's OAuth configuration is incomplete» y Publish app queda en gris.

/privacy responde 200 porque la SPA sirve cualquier ruta, así que la URL vale para publicar — Google solo revisa el contenido en la verificación, que con drive.file no hace falta. Pero ahí no hay ninguna política todavía. Es deuda pendiente, no algo resuelto.

4 Crear el cliente OAuth

  1. Google Auth Platform → Clients.
  2. Botón Create client.
  3. Rellena con la tabla de abajo.
  4. Botón Create.
Campo Qué poner
Application type Web application
Name marketing-ai-manager — solo lo ves tú en la consola.
Authorized JavaScript origins Dejar vacío. No es este.
Authorized redirect URIs Este sí. Pulsa Add URI dos veces y pega una en cada línea: 
https://mazzeflow.com/api/v1/auth/google/callback
http://localhost/api/v1/auth/google/callback

Copia el secreto ahora

Al pulsar Create aparecen Client ID y Client secret. El secreto se muestra una sola vez. Pulsa Download JSON o cópialo a un sitio seguro. Si lo pierdes, hay que crear otro.

5 Habilitar Google Drive API

Antes de los scopes: drive.file no aparece en la lista del paso 6 si la API de Drive no está habilitada.

  1. Menú ☰ → APIs & Services → Library.
  2. Busca Google Drive API → ábrela → Enable.
  3. YouTube Data API v3: sáltala. Su scope es sensible y la feature está apagada — ver el aviso del paso 6.

6 Declarar los cuatro scopes

  1. Google Auth Platform → Data access.
  2. Botón Add or remove scopes.
  3. Marca los cuatro de la tabla. Los tres primeros salen en la lista; drive.file se pega en Manually add scopes y se pulsa Add to table.
  4. Update y luego Save.
Scope Para qué
openidEntrar
emailEntrar
profileNombre y avatar
https://www.googleapis.com/auth/drive.fileBiblioteca de piezas

No añadas youtube.readonly todavía

Es un scope sensible. Al añadirlo, Data access lo mete en «Your sensitive scopes — Approval required» y pide una justificación: la app entra en revisión manual de Google, que tarda semanas y exige política de privacidad real y vídeo de demostración.

Y lo pedirías para nada: features.youtube está en false en config/settings.php, y la aplicación solo envía ese scope cuando alguien conecta YouTube desde Integraciones. Con el flag apagado, nunca se pide.

Si ya lo añadiste: papelera en su fila, borra la justificación, Save. Los otros cuatro no son sensibles y publican sin aprobación.

Cuando la parte de YouTube esté construida se añade el scope y se pasa la verificación entonces, con la app en marcha y algo real que enseñar.

7 Publicar la app

  1. Google Auth Platform → Audience.
  2. En Publishing status pulsa Publish app.
  3. Confirma. Debe quedar In production.

Este es el paso que no se puede saltar

En Testing, Google dice textualmente:

Authorizations by a test user will expire seven days from the time of
consent. If your OAuth client requests an offline access type and
receives a refresh token, that token will also expire.

Traducido: funciona hoy y a los siete días todos los usuarios pierden Drive y YouTube a la vez. El refresh empieza a devolver invalid_grant y hay que reconectar cuenta por cuenta.

No hace falta verificación para publicar con estos scopes: drive.file no es sensible. La verificación aparece con scopes más amplios.

8 Pegar las credenciales

Las dos líneas, en el src/.env del entorno que toque:

GOOGLE_CLIENT_ID=el Client ID del paso 4
GOOGLE_CLIENT_SECRET=el Client secret del paso 4
Entorno Fichero Después
Local src/.env Nada más.
Producción /var/www/marketing-ai-manager/src/.env Rehacer la caché de configuración, o el cambio no surte efecto: 
./scripts/deploy.sh

GOOGLE_REDIRECT_URI ya viene puesto en los dos sitios. No lo toques.

9 Probar

  1. Abre https://mazzeflow.com o http://localhost.
  2. Entra con Google.
  3. Debe salir la pantalla de consentimiento con el App name del paso 2, y volver a la aplicación ya autenticado.
Error Causa
redirect_uri_mismatch El URI del paso 4 no coincide carácter por carácter. Revisa http vs https, el puerto y la barra final.
invalid_grant a los 7 días Sigue en Testing. Paso 7.
access_blocked Falta el paso 2 o el 3: sin App name y User support email la pantalla de consentimiento no se puede mostrar.
Falla la llamada a Drive o YouTube Paso 5. El token es válido pero la API no está habilitada.
La segunda conexión no da refresh token Normal: Google solo lo entrega en el primer consentimiento. La aplicación manda siempre access_type=offline y prompt=consent para forzarlo.
